# HF Spaces Telegram Webhook Configuration

## What Changed
Switched from **polling mode** (blocked by HF network restrictions) to **webhook mode**.

### How It Works

**Before (Polling - BLOCKED):**
```
Hermes Agent → tries to connect to → api.telegram.org
[times out - HF Spaces blocks outbound]
```

**After (Webhook - WORKS):**
```
Telegram Server → pushes message to → https://huggingface.co/spaces/Jishnupg/MyHermesAgent
Hermes Agent receives & responds ← processes locally
```

## Configuration

Added to config.yaml:
```yaml
telegram:
  webhook_mode: true
  webhook_base_url: "https://huggingface.co/spaces/Jishnupg/MyHermesAgent"
  webhook_path: "/webhook"
```

## Auto-Registration

On startup, the container automatically:
1. Registers webhook with Telegram: `setWebhook` API call
2. Sets webhook URL to HF Spaces space
3. Drops any pending updates (clean slate)

## How to Test

After the build completes (~5 minutes):

1. **Send a message** to your Telegram bot: `@Jishnupg_MyHermesAgent_bot`

2. **Expected flow:**
   - Message sent to Telegram
   - Telegram pushes to webhook endpoint
   - Hermes Agent receives & processes
   - Response generated by Claude 3.5 Sonnet
   - Reply sent back to you

3. **Check logs** in HF Spaces dashboard:
   - Should see "Registering Telegram webhook..."
   - Should see "✓ Webhook registered"

## Why This Works on HF Spaces

✅ HF Spaces ALLOWS inbound HTTPS traffic (port 7860)
✅ HF Spaces BLOCKS outbound to telegram.org
✅ Webhook mode only needs inbound (no outbound needed)

## Benefits
- ✅ No polling = no timeouts
- ✅ Real-time response (immediate delivery)
- ✅ Lower latency (no retry delays)
- ✅ Lower resource usage

## Webhook Endpoint
- URL: `https://huggingface.co/spaces/Jishnupg/MyHermesAgent/webhook`
- Method: POST
- Handler: Built into Hermes gateway (no additional config)
